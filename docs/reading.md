# Как читать этот репозиторий

Текст для человека, которому нужно за несколько минут понять, какое решение
здесь принимается и чего здесь нет. Формулы — в
[постановке](mathematical-formulation.md), команды — в [README](../README.md).

Автор не связан с KAMAZ Digital, ПАО «КАМАЗ», ПАО «НефАЗ» и другими
названными компаниями и не пользовался их внутренними сведениями. Названия
систем и компаний принадлежат правообладателям. Данных заказчика и пилотного
внедрения в репозитории нет: открытые эталоны и синтетические дни.

## Какое решение принимает программа

На входе день: заказы, машины, дороги, правила. На выходе — какая машина
забирает какой заказ, в каком порядке и к какому времени. Рядом отдельная
программа пересчитывает тот же план и либо подтверждает его, либо называет,
какие условия друг другу мешают и сколько минут не хватает. Поиск и проверка
не делят код: проверяющий не может «поверить» решателю.

Заказ — это доставка со склада, сбор на склад или пара «забрал здесь —
отвёз туда». У груза несколько измерений сразу (килограммы, кубометры,
паллеты). Машины разные: своя уже оплачена и стоит только пробега и времени,
наёмная берёт плату за выход и более дорогой тариф. Окно говорит, когда
стоянку можно обслужить. Перерыв водителя — не пожелание, а ограничение:
после 4,5 часа за рулём 45 минут, либо 15 и затем 30 (приказ Минтранса № 160,
пункты 8 и 11). Заявка может прийти не с утра, а в середине смены: уже
проехавшее не переписывается.

Это и есть задача маршрутизации со смешанным парком. В литературе её части
называются VRPTW (окна), PDPTW (забор и доставка) и DARP (перевозка людей с
лимитом времени в пути). В коде это одна модель.

## Один день, который можно пересчитать

Заводская смена seed 11 собрана генератором: 140 заявок цехов, девять машин
трёх типов, координаты на площадке, не с предприятия. Два запуска одной и той
же смены. Левая колонка — заявки приходят по ходу дня, ответ даёт вставка без
переоптимизации. Правая — все заявки известны с утра, план ищет ALNS на 5000
итерациях. Seed 5 в таблице диспетчера — другой день, числа оттуда сюда не
переносятся.

| | Заявки по ходу смены (вставка) | Все заявки с утра (ALNS) |
| --- | ---: | ---: |
| Выполнено заявок | 134 из 140 | 138 из 140 |
| Пробег, км | 611,3 | 444,6 |
| Порожний пробег, км | 210,0 | 95,4 |
| Коэффициент использования пробега | 65,6% | 78,5% |
| Стоимость | 59 232 | 50 514 |

Из 166,7 км разницы 114,6 км машина едет пустой: не зная следующей заявки, она
после выгрузки стоит на месте и к новой погрузке идёт без груза. Обеим
колонкам не хватает одних и тех же двух заявок, M020 и M120. Это крытые грузы
4 паллеты и 1560 кг, 6 паллет и 1510 кг; крытый фургон берёт 4 паллеты и
1500 кг, так что ни один тип машины их не везёт. Из шести отказов диспетчера
два названы этой причиной, остальные четыре — «все машины, что успевают,
заняты». Команды — в [заводском транспорте](industrial-transport.md).

## Какой метод когда

Метод выбирается по размеру задачи и по тому, сколько есть времени на ответ.

| Ситуация | Метод | Что от него можно ждать |
| --- | --- | --- |
| Малая задача, нужен доказанный оптимум | CP-SAT; та же постановка как MIP на SCIP, HiGHS и CBC | На 40 случайных задачах полной модели по 8 заказов CP-SAT доказал оптимум, ALNS с ним совпал. Время в пути в точной модели округлено вверх до 0,01 мин, оба плана оценивает верификатор |
| План на утро, заказов много | ALNS: разрушение и сборка маршрутов | хороший план, не доказательство. Разрыв к лучшему известному решению опубликован по каждому открытому эталону |
| Заявка пришла сейчас | вставка в непроехавшую часть маршрута | ответ за доли миллисекунды. Уже обещанное время не сдвигается |
| Раз в полчаса есть время переложить хвосты | тот же ALNS по живому состоянию | новый порядок принимается, только если перерыв водителя остаётся законным и проверенная стоимость дня падает |
| Чужой решатель на той же задаче | OR-Tools Routing | сравнение на одном верификаторе. Перерыва водителя у OR-Tools нет, такой день он не считает |

Поиск на ядре Rust и поиск на Python дают один и тот же план. Rust здесь
ускорение горячего цикла, а не второй алгоритм. Цены разбиения множества
точны для уже построенного пула маршрутов и остаются оценкой для всех
маршрутов, которых в пуле нет.

| Документировать алгоритмы и ревью | постановка с леммами; CI не принимает расхождение ядра и эталона | ревью здесь — проверки в запросах на слияние, не процесс чужой команды |
| Объяснить решение и границы человеку без этой специальности | этот текст и [сайт](https://konkovdv.github.io/SynAPS-MobiRoute/) | — |

Теория, которую описание просит узнавать в коде: линейное и целочисленное
программирование (точные модели и двойственные цены пула маршрутов), графы
(разностные ограничения и кратчайшие пути для расписания), комбинаторный
поиск (ALNS, локальный поиск, разбиение множества маршрутов). Солверы в
репозитории: CP-SAT, SCIP, HiGHS, CBC, GLOP, OR-Tools. Код на Python
разложен по объектам с одной задачей, покрыт тестами, ускорение начиналось с
профиля (`docs/native-acceleration.md`).

## Куда нажать дальше

1. [Сайт](https://konkovdv.github.io/SynAPS-MobiRoute/) — смена цехов, перерыв
   по приказу № 160, маршрут, который можно сломать и увидеть сертификат.
2. `mobiroute vrp-dispatch --day plant --seed 11 --orders 140` — левая
   колонка таблицы: заявки по ходу смены, вставка без переоптимизации.
3. `mobiroute vrp-solve --generate plant --seed 11 --orders 140` — правая
   колонка: все заявки известны с утра, ALNS на 5000 итерациях.
4. [Постановка](mathematical-formulation.md) — если нужна математика, а не
   пересказ.
5. [Ограничения](limitations.md) — полный список того, что модель пока не
   умеет.

## English

The program decides which vehicle takes which order, in which order and at
what time, and a separate program checks that the trip can be driven. If it
cannot, the check names the conflicting rules and the minutes missing. The
repository is public benchmarks plus synthetic days. It is not affiliated
with KAMAZ Digital or any other company named in the docs, and it has not
been run on a customer's data or put into a carrier's operation. The table
above maps the public job description of KAMAZ Digital's algorithmic
programmer role (Saint Petersburg, hybrid; retold on h.careers, read on
15 November 2026) onto files in this repository, including the parts that
description asks for and this code does not have.
