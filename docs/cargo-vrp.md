# Грузовой VRP со смешанным парком

Язык: **RU** | [EN](#english-summary)

Пакет `mobiroute.vrp` решает задачу маршрутизации, в которой у каждого заказа
есть окна, вес, объём и паллеты, требования к кузову и к допуску, а у парка —
несколько типов машин, свои и наёмные, с разной стоимостью, скоростью и
длительностью смены. Это тот же класс задач, что пассажирский DARP, но с
грузовыми единицами и экономикой парка; пассажирские сценарии (шаттл по
требованию) решаются той же моделью.

## Модель

| Понятие | Как задаётся | Пример |
| --- | --- | --- |
| Заказ «забор → доставка» | `Request(pickup, delivery)` | поставщик → клиент |
| Доставка со склада | `Request(None, delivery)`, груз на борту с начала рейса | РЦ → магазин (VRPTW) |
| Сбор на склад | `Request(pickup, None)` | возврат тары |
| Вектор ёмкости | `demand`, `capacity` любой размерности | кг, м³, паллеты |
| Требования к машине | `skills` заказа ⊆ `skills` типа | гидроборт, рефрижератор, ДОПОГ, кран |
| Типы машин | `VehicleType`: количество, депо, смена, профиль скорости | фургон 1,5 т, 5 т, 10 т, тягач 20 т |
| Свои и наёмные | свои: только переменные затраты; наёмные: плата за выход + тариф выше | решение нанимает, только когда своих не хватает |
| Стоимость | `fixed_cost + руб/км × км + руб/ч × (движение + обслуживание)` | |
| Окна | начало обслуживания в `[earliest, latest]` | слот разгрузки у клиента |
| Смена водителя | `max_duration`: от выезда до возврата | 10 часов |
| Время в пути груза | `max_ride` для пары | скоропортящийся груз |
| Профили дорог | матрицы времени и расстояния на тип | грузовик медленнее фургона |

Формально — [mathematical-formulation.md](mathematical-formulation.md), раздел 1.

## Как решается

1. **Построение.** Regret-2: на каждом шаге вставляется заказ, у которого
   разница между лучшим и вторым вариантом наибольшая — сначала те, кому
   «некуда деться».
2. **Вставка за O(1).** Для маршрута хранятся самое раннее и самое позднее
   начало обслуживания на каждой остановке и загрузка по каждому измерению.
   Проверка окна, ёмкости и навыков — арифметика; кратчайшая длительность рейса
   после вставки — по готовой формуле из префиксных и суффиксных экстремумов.
   Лимит времени в пути проверяется точно (Беллман–Форд) только для самых
   дешёвых кандидатов.
3. **ALNS.** Разрушение: случайное, худшие, связанные (Shaw), цепочки с соседних
   маршрутов (SISR), маршрут целиком; восстановление: regret-1/2/3, с шумом и
   без; веса операторов адаптируются, приём решений — имитация отжига.
4. **Меньше машин.** Убираем маленький маршрут и возвращаем его заказы методом
   guided ejection: вставка ценой выталкивания не более двух других заказов с
   наименьшими штрафами, затем возмущение.
5. **Тип машины для маршрута.** Вставка открывает машину ради одного заказа,
   поэтому тип с большой платой за выход сам по себе не выбирается никогда, даже
   если весь маршрут на нём дешевле. После каждого восстановления типы
   маршрутов выбираются заново и точно — как транспортная задача (поток
   минимальной стоимости «маршрут → тип», не больше `count` машин типа).
6. **Ядро на Rust.** Восстановление, вставка, точная проверка расписания и шаг
   выталкивания выполняются в `VrpKernel`. Результат совпадает с эталоном на
   Python бит в бит, вплоть до всей траектории ALNS; быстрее в 12–42 раза
   ([benchmarks/vrp-speed.md](benchmarks/vrp-speed.md)).

## Как проверяется

* **Независимый верификатор** пересчитывает загрузку, расписание и стоимость
  любого плана — эвристики, CP-SAT или OR-Tools — и ничего не берёт у решателя.
* **Сертификат «почему нельзя».** Если рейс невозможен, верификатор возвращает
  отрицательный цикл в графе ограничений: какие условия конфликтуют и сколько
  минут не хватает. Пример с грузового дня: *поставщик открывается в 09:00,
  погрузка 26 мин, переезд 162,8 мин, клиент принимает до 12:00 — не хватает
  8,8 мин*. Логист сразу видит, что менять: окно клиента или время у поставщика.
* **Точная модель.** CP-SAT с отдельным циклом на каждую машину доказывает
  оптимум на малых задачах: на 40 случайных задачах полной модели ALNS находит
  доказанный оптимум в 38 случаях, средний разрыв 0,13%
  ([benchmarks/exact-vs-alns.md](benchmarks/exact-vs-alns.md)).
* **Открытые эталоны.** Solomon, Li & Lim, Sartori–Buriol (реальные дорожные
  времена OSRM), Cordeau — разрыв к лучшим известным решениям по каждому
  инстансу ([benchmarks/vrp-public-benchmarks.md](benchmarks/vrp-public-benchmarks.md)).
* **OR-Tools.** Та же модель в OR-Tools Routing (PCI + GLS) при равном времени,
  тот же верификатор: на грузовых днях ALNS дешевле на 19% и обходится меньшим
  числом машин, на открытых эталонах не хуже нигде
  ([benchmarks/ortools-vs-alns.md](benchmarks/ortools-vs-alns.md)).

## Сценарии

**Городская доставка со своим и наёмным парком** (`generators.cargo_day`). Два
депо, 4 класса машин, своих и наёмных, вектор кг/м³/паллеты, рефрижератор,
гидроборт, ДОПОГ, слоты доставки, смена 10 часов. На дне из 60 заказов решение
обходится своими машинами; на 120 заказах добавляет наёмные только того класса,
которого не хватает.

**Внутризаводская логистика в реальном времени** (`generators.plant_day`,
`realtime.Dispatcher`). Перевозки паллет между цехами и складами появляются в
течение смены; тягачи, бортовые машины с краном, крытый фургон. Каждая заявка
получает ответ за доли миллисекунды: вставка в ту часть плана, которую машина
ещё не проехала, или отказ с причиной. Раз в 30 минут живое состояние
переоптимизируется ALNS. Метрики: доля принятых заявок, время подачи (от
заявки до прибытия машины), стоимость. Для сравнения — пересчёт всего живого
состояния в OR-Tools на каждую заявку: на 1,4 п. п. больше принятых заявок и на
2,5% дешевле, но 2,9 с на решение вместо 0,1 мс и подача машины в среднем на
5 минут позже ([benchmarks/realtime-dispatch.md](benchmarks/realtime-dispatch.md)).

**Корпоративный шаттл по требованию** (`generators.shuttle_day`). Поездки
между остановками; ожидание не больше 30 минут, ожидание плюс поездка не
больше 45 минут, микроавтобусы на 8 мест. Ограничение «ожидание + поездка»
записывается точно — как крайний срок высадки.

## Запуск

```bash
mobiroute vrp-solve --generate cargo --orders 120 --out-dir out-cargo --svg
mobiroute vrp-solve --instance benchmark/instances/sartori-buriol/n100/bar-n100-1.txt --time-limit 10 --out-dir out-sb --svg
mobiroute vrp-solve --generate cargo --orders 60 --solver ortools --time-limit 10 --out-dir out-ortools
mobiroute vrp-dispatch --day plant --policy insertion+alns --out-dir out-plant
```

```python
from mobiroute.vrp import AlnsConfig, solve
from mobiroute.vrp.generators import cargo_day

day = cargo_day(7, n_orders=120)
result = solve(day, AlnsConfig(time_limit=10, seed=1))
print(result.verdict.summary(), result.verdict.cost.vehicles_by_type)
```

## English summary

`mobiroute.vrp` routes a heterogeneous own-and-hired fleet: capacity vectors
(kg, m³, pallets), skills (tail lift, refrigeration, ADR, crane), per-type
speed profiles, fixed and variable costs, shift caps, time windows,
pickup-and-delivery pairs, depot deliveries and collections, ride limits.
Insertion tests run in constant time (forward/backward slack, a closed-form
shortest duration); ALNS with five ruin operators, regret repair and guided
ejection does the search; the repair runs in a Rust kernel that reproduces the
Python reference bit for bit. Every plan is checked by an independent verifier
that returns why-not certificates. Results: public benchmarks, ALNS against
CP-SAT proven optima, OR-Tools Routing at equal time, and live dispatch on
synthetic plant, shuttle and freight days — see `docs/benchmarks/`.
